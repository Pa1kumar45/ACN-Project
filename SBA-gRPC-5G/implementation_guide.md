## Part A — LSTM vs Reinforcement Learning: Head-to-Head

### The Shared Goal
Both predict/decide WHEN to boot a new AMF so it's ready before the traffic surge arrives,
eliminating the 40-second cold-start lag.

---

### Option 1: LSTM Time-Series Forecaster

```
Past 60s of request rates  →  LSTM  →  Predicted load at t+40s  →  Scale-up signal
```

| Dimension | Detail |
|-----------|--------|
| **What it learns** | Temporal patterns in request arrival rate (e.g., daily peaks, Poisson bursts) |
| **Training data** | `arrivalsAtTime[]` already generated by `ran_simulator.cpp`'s Poisson scheduler |
| **Input** | Sliding window of last N=60 seconds of request counts |
| **Output** | Scalar: predicted request/sec at time t+40s |
| **Trigger rule** | `if predicted_rps > threshold_per_AMF * current_AMF_count: scale_up()` |
| **Model size** | ~50KB — runs in microseconds per inference |
| **Training time** | Minutes on a laptop (offline, not real-time) |
| **Library** | PyTorch / TensorFlow / scikit-learn (Random Forest variant) |
| **Pros** | ✅ Simple, interpretable, fast to train, works well with periodic traffic |
| **Cons** | ❌ Can't adapt to unseen traffic patterns without retraining; needs historical data |

---

### Option 2: Deep Reinforcement Learning (DRL)

```
Current State (load, #AMFs, queue depth)  →  DRL Agent  →  Action (scale up/down/hold)
Reward: -latency - cost_of_idle_AMFs
```

| Dimension | Detail |
|-----------|--------|
| **What it learns** | Optimal scaling POLICY under any traffic condition |
| **Training** | Agent interacts with a simulated 5G network environment (or the real one) |
| **State** | [current_rps, #active_AMFs, avg_cpu, queue_depth, time_of_day] |
| **Actions** | {scale_up_by_1, scale_down_by_1, hold} |
| **Reward** | `-(latency) - α*(idle_AMF_cost)` — balances QoS vs cost |
| **Algorithm** | PPO / DQN / A3C |
| **Pros** | ✅ Adapts to unseen patterns; optimizes multi-objective (latency + cost) |
| **Cons** | ❌ Complex reward shaping; unstable training; needs thousands of episodes; slower inference |

---

### LSTM vs RL Comparison Table

| Aspect | LSTM Forecaster | Deep RL (DRL) |
|--------|----------------|---------------|
| **Approach** | Supervised prediction | Reinforcement policy |
| **Output** | Future load value | Scaling action |
| **Training data needed** | Historical traffic logs | Simulated environment |
| **Time to train** | Minutes | Hours–Days |
| **Inference speed** | <1ms | <5ms |
| **Adapts to unseen patterns** | ❌ (needs retraining) | ✅ (policy generalizes) |
| **Interpretability** | Medium (you see predicted value) | Low (black box policy) |
| **Implementation complexity** | 🟡 Medium | 🔴 Hard |
| **Risk of instability** | Low | Medium-High |
| **Matches ScaleLB future work quote** | ✅ ("prediction approach") | ✅ ("ML-based") |
| **Best for course project** | ✅ **RECOMMENDED** | Ambitious but risky |

> **Verdict for your project: Use LSTM.** It directly matches the paper's quoted future work
> ("a machine learning based *prediction* approach"). RL is a different paradigm — harder to
> justify as an extension of *this specific paper* without a complete simulator environment.

## Part B — Integration: Python ML + Existing C++/Go Codebase

### The Critical Question: Do You Need to Rewrite Everything?

**NO. Absolutely not.**

The architecture uses a **Microservice / Sidecar pattern**. The Python ML module runs
as an independent service that communicates with the Go load balancer via a lightweight
REST API. The C++ NFs don't even know it exists.

### How the Integration Works

```
┌─────────────────────────────────────────────────────────┐
│                   Docker Network (vepc)                  │
│                                                          │
│  ┌─────────┐    ┌──────────────────────┐                │
│  │   RAN   │    │   Load Balancer (Go)  │                │
│  │  (C++)  │───►│   grpclb/server.go    │                │
│  └─────────┘    │                      │  HTTP REST      │
│                 │  Every 5s: GET        │◄──────────────►│
│  ┌─────────┐    │  /predict?window=60  │                │
│  │   AMF   │    └──────────┬───────────┘  ┌────────────┐│
│  │  (C++)  │               │              │ ML Service  ││
│  └─────────┘          gRPC │              │  (Python)   ││
│                            ▼              │             ││
│               ┌──────────────────────┐   │ LSTM model  ││
│               │  AUSF/SMF replicas   │   │ Flask API   ││
│               │  (C++ containers)    │   └────────────┘│
│               └──────────────────────┘                  │
└─────────────────────────────────────────────────────────┘
```

### Language Boundaries — Clean & Simple

| Layer | Language | Change Needed |
|-------|----------|---------------|
| 5G NFs (AMF/AUSF/SMF/UPF) | **C++** | Phase 1 changes only |
| Load Balancer | **Go** | Phase 1 + HTTP client to ML service |
| ML Predictor | **Python** | New microservice |
| Consul (NRF) | Binary | No change |
| Docker Compose | YAML | Add ml_service container |

**The Python ML service exposes ONE endpoint:**
```
GET /predict
Response: {"predicted_rps": 850.3, "scale_up": true, "scale_to": 3}
```

The Go LB polls this every 5 seconds. If `scale_up: true`, it calls the Docker API
(or Consul) to spin up another AMF container. That's it.

```go
// NewConsistentHashBalancer returns a balancer that uses jump consistent hashing.
// imsiKey is the UE's IMSI extracted from gRPC metadata.
// Bounded load: if chosen server load > 1.25 * avg_load, spill to next.
func NewConsistentHashBalancer(imsiKey string) Balancer {
    return BalancerFunc(func(s []*balancerpb.Server) *balancerpb.Server {
        if len(s) == 0 {
            return nil
        }
        if imsiKey == "" {
            // fallback to random for non-UE traffic
            return s[rand.Intn(len(s))]
        }

        // Jump consistent hash: map IMSI string to bucket [0, len(s))
        h := fnv32(imsiKey)
        idx := jumpHash(int64(h), int64(len(s)))

        // Bounded load: spill over if target is overloaded
        // Check cpu tag of chosen server
        chosenCPU := getCPUTag(s[idx])
        avgCPU := avgCPUOfServers(s)
        if chosenCPU > avgCPU*1.25 {
            // Move to next server on the ring
            idx = (idx + 1) % len(s)
        }
        return s[idx]
    })
}

// jumpHash implements Google's Jump Consistent Hash
func jumpHash(key int64, numBuckets int64) int64 {
    var b, j int64 = -1, 0
    for j < numBuckets {
        b = j
        key = key*2862933555777941757 + 1
        j = int64(float64(b+1) * (float64(int64(1)<<31) / float64((key>>33)+1)))
    }
    return b
}

func fnv32(s string) uint32 {
    h := uint32(2166136261)
    for _, c := range []byte(s) {
        h ^= uint32(c)
        h *= 16777619
    }
    return h
}

func getCPUTag(s *balancerpb.Server) float64 {
    for _, tag := range s.Tags {
        if strings.Contains(tag, "cpu:") {
            if v, err := strconv.ParseFloat(tag[4:], 64); err == nil {
                return v
            }
        }
    }
    return 50.0  // default if no tag
}

func avgCPUOfServers(s []*balancerpb.Server) float64 {
    total := 0.0
    for _, srv := range s {
        total += getCPUTag(srv)
    }
    return total / float64(len(s))
}
```

## Part E — ML Auto-Scaling: Complete New Python Service

### New file: `src/ml_autoscaler/predictor.py`

```python
import numpy as np
import time
import requests
import json
from collections import deque
from sklearn.ensemble import RandomForestRegressor  # start simple
# from tensorflow.keras.models import Sequential    # upgrade to LSTM later
# from tensorflow.keras.layers import LSTM, Dense

class TrafficPredictor:
    """
    Lightweight time-series predictor for AMF load.
    Reads request rates from Prometheus/Consul, predicts 40s ahead,
    signals when to pre-emptively scale.
    """
    WINDOW_SIZE = 60       # seconds of history
    LOOKAHEAD = 40         # seconds to predict ahead (AMF boot time)
    SCALE_THRESHOLD = 0.75 # scale up if predicted load > 75% of capacity
    AMF_CAPACITY = 100     # requests/sec per AMF (tune to your setup)

    def __init__(self, consul_url="http://192.168.136.88:8500"):
        self.consul_url = consul_url
        self.request_history = deque(maxlen=self.WINDOW_SIZE)
        self.model = RandomForestRegressor(n_estimators=50)
        self.trained = False
        self.training_data = []

    def collect_metrics(self):
        """Pull current request rate from Consul service tags."""
        try:
            r = requests.get(f"{self.consul_url}/v1/agent/services", timeout=2)
            services = r.json()
            total_rps = 0
            for name, svc in services.items():
                for tag in svc.get("Tags", []):
                    if tag.startswith("responseTime:"):
                        # Estimate RPS from response time tag (inverse)
                        rt = float(tag.split(":")[1])
                        total_rps += 1000.0 / max(rt, 1)
            return total_rps
        except Exception:
            return len(self.request_history) > 0 and self.request_history[-1] or 0

    def update(self, current_rps):
        """Add new data point and retrain periodically."""
        self.request_history.append(current_rps)
        self.training_data.append(current_rps)

        # Retrain every 120 seconds once we have enough data
        if len(self.training_data) >= self.WINDOW_SIZE + self.LOOKAHEAD:
            self._train()

    def _train(self):
        """Train model: predict rps[t+LOOKAHEAD] from rps[t-WINDOW:t]."""
        data = np.array(self.training_data)
        X, y = [], []
        for i in range(self.WINDOW_SIZE, len(data) - self.LOOKAHEAD):
            X.append(data[i - self.WINDOW_SIZE:i])
            y.append(data[i + self.LOOKAHEAD])
        if len(X) > 10:
            self.model.fit(X, y)
            self.trained = True

    def predict(self):
        """Predict load 40 seconds from now."""
        if not self.trained or len(self.request_history) < self.WINDOW_SIZE:
            # Fallback: use current rate
            return self.request_history[-1] if self.request_history else 0

        features = np.array(list(self.request_history)).reshape(1, -1)
        return float(self.model.predict(features)[0])

    def scaling_decision(self, num_active_amfs):
        """Return (scale_up: bool, target_count: int)."""
        predicted = self.predict()
        capacity = num_active_amfs * self.AMF_CAPACITY
        utilization = predicted / max(capacity, 1)

        if utilization > self.SCALE_THRESHOLD:
            new_count = int(np.ceil(predicted / (self.AMF_CAPACITY * self.SCALE_THRESHOLD)))
            return True, new_count
        elif utilization < 0.3 and num_active_amfs > 1:
            # Scale down
            new_count = max(1, int(np.floor(predicted / (self.AMF_CAPACITY * 0.6))))
            return False, new_count
        return False, num_active_amfs
```

### New file: `src/ml_autoscaler/server.py`

```python
from flask import Flask, jsonify, request as flask_request
import threading
import time
from predictor import TrafficPredictor

app = Flask(__name__)
predictor = TrafficPredictor()
num_active_amfs = 1  # updated by Docker/Consul

def background_collector():
    """Collect metrics every second."""
    while True:
        rps = predictor.collect_metrics()
        predictor.update(rps)
        time.sleep(1)

@app.route('/predict', methods=['GET'])
def predict():
    scale_up, target = predictor.scaling_decision(num_active_amfs)
    return jsonify({
        "predicted_rps": predictor.predict(),
        "current_rps": predictor.request_history[-1] if predictor.request_history else 0,
        "scale_up": scale_up,
        "scale_to": target,
        "current_amfs": num_active_amfs
    })

@app.route('/amf_count', methods=['POST'])
def update_amf_count():
    global num_active_amfs
    data = flask_request.json
    num_active_amfs = data.get('count', 1)
    return jsonify({"ok": True})

if __name__ == '__main__':
    t = threading.Thread(target=background_collector, daemon=True)
    t.start()
    app.run(host='0.0.0.0', port=8080)
```
